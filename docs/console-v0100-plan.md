# v0.10.0：harness 与统一任务调度

目标：最多三个活跃工作流，共享一个模型实例。推理槽位独立配置；本地模拟三路，生产默认一路，三路真实推理经服务器压测后启用。排队不冻结额度。SimCourt 空闲页面不占名额，一次庭审是一个工作流，其模型调用是子请求

本轮在本地实现和验证，不操作真实模型、云端账号或现有站点。新增表兼容原数据库，不删除历史任务、Key 或用量。上线前在线备份数据库；旧版回退保留新增表，未知已提交调用进入对账，不自动重放

## 验收

- OpenAI Chat Completions 支持真实 SSE、中间工具调用、tool 结果、developer 角色与输出长度别名；提供 Anthropic Messages 适配。Responses 未实现时明确返回不支持
- 输入仅支持文本和函数工具；不透传任意上游地址、回调或宿主命令。网关不执行模型生成的工具
- 一个持久化调度器接管同步 API、异步 API、带任务 ID 的 harness 和 SimCourt；最多三个工作流活跃，超出等待。已有 Key 的并发设置保留
- 成员仅能读取自己的任务、状态及前方排队人数；管理员能看到成员归属。查询他人任务及取消他人任务必须失败
- 排队和派发事务化；同一幂等键不重复提交。重启恢复排队项，已派发状态不明的调用不重试；未知调用占用保护名额，等待人工对账
- 取消未派发调用不调用上游；运行中的取消只取消对应请求，不停止共享模型。用量缺失时不得伪造零用量成功
- 长队列异步接口返回任务 ID；标准同步 API 只进行有界等待，超时取消尚未派发项并返回 429/Retry-After。HTTP 客户端断开不等于取消服务端已接收的任务
- UI：我的任务显示自己的任务与前方人数；管理员显示归属和全局状态；顶部显示活跃工作流、推理占用和等待数，后台同步不重绘草稿
- SimCourt 使用专属普通成员调用 Key，经统一网关逐次调用；工作流开头创建任务、运行中续租、结束释放，不再绕过网关直连模型。提供适配器和可审核部署步骤，不声称已改生产
- 独立验证三工作流重叠、第四项排队、公平性、权限、重启、超时、流式计量、断线与未知结果；真实三路长上下文/GPU峰值另行验收

## 接口

`POST /v1/jobs` 创建显式工作流，`GET /v1/jobs/{id}` 查询，`POST /v1/jobs/{id}/heartbeat|finish|cancel` 管理生命周期，`POST /v1/jobs/{id}/calls` 提交持久化异步聊天，`GET /v1/calls/{id}` 获取状态和结果。标准聊天通过 `X-Task-ID` 关联工作流，无任务 ID 的请求按单次调用计任务。需要客户端适配才能把整个 harness 会话识别为一个任务

Web 会话通过 `/api/jobs` 查看和取消；普通网页会话不能代替调用 Key 提交推理。任务记录不提供服务器上的任意命令执行能力。任务租约300秒，适配器每30秒续租；无在途请求的过期任务释放，结果不明的在途请求保持对账保护
